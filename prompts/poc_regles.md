# Règles de code
- Une seule bascule de données : `PHASE`. Fonctions d'entraînement, d'inférence et d'évaluation définies une fois et appelées dans les deux phases.
- Modèles : charge **tout** modèle par `model_path("org/nom")`, dans les deux phases (en phase private, il est servi hors ligne depuis un dossier local, cache Hugging Face vide : un chargement direct par identifiant y échoue). Phase private : LLM par `llm_chat` (ou `openai_client("LLMAAS")`), transcription par `transcribe` (ou `openai_client("STTAAS")`), embeddings par `embed_texts`. Jamais de clé, d'URL ni de nom de modèle de service en dur : tout vient de l'environnement. Aucune donnée interne brute affichée : `preview(df)`, effectifs et agrégats seulement.
- Phase publique : aucun appel à un service externe ; modèles Hugging Face exécutés localement sur `device()`. `trust_remote_code=True` seulement avec `revision="<sha>"` épinglé (sha fourni dans les faits vérifiés).
- Deux échelles, un seul code. Ce qui change passe par `by_scale(reduced=..., full=...)` (substitut de `modeles_hf_sandbox`, nombre d'époques ou de pas, longueur des séquences) ou `sample_size` (échantillons) ; rien d'autre ne diffère.
  - Échelle réduite (`SCALE == "reduced"`) : tout le notebook en quelques minutes sur 2 cœurs CPU et ~5 Go de RAM, téléchargements compris : quelques centaines d'exemples, une époque, séquences courtes, lots modestes.
  - Échelle complète (`SCALE == "full"`) : tout le jeu, sur `device()`.
