# Règles de code
- Une seule bascule : `PHASE`. Fonctions d'entraînement, d'inférence et d'évaluation définies une fois et appelées dans les deux phases.
- Modèles : charge **tout** modèle par `chemin_modele("org/nom")`, dans les deux phases (en phase banque, le sandbox les sert hors ligne depuis un dossier local, cache Hugging Face vide : un chargement direct par identifiant y échoue). Phase banque : LLM par `llm_chat` (ou `client_openai("LLMAAS")`), STT par `stt_transcrire` (ou `client_openai("STTAAS")`), embeddings par `embeddings`. Jamais de clé, d'URL ni de nom de modèle de service en dur : tout vient de l'environnement. Aucune donnée bancaire brute affichée : `apercu(df)`, effectifs et agrégats seulement.
- Phase publique : aucun appel à un service externe ; modèles Hugging Face exécutés localement sur `appareil()`. `trust_remote_code=True` seulement avec `revision="<sha>"` épinglé (sha fourni dans les faits vérifiés).
- Deux échelles, un seul code. Ce qui change passe par `selon_taille(sandbox=..., complete=...)` (substitut de `modeles_hf_sandbox`, nombre d'époques ou de pas, longueur des séquences) ou `taille_echantillon` (échantillons) ; rien d'autre ne diffère.
  - Échelle réduite (`TAILLE == "sandbox"`) : tout le notebook en quelques minutes sur 2 cœurs CPU et ~5 Go de RAM, téléchargements compris : quelques centaines d'exemples, une époque, séquences courtes, lots modestes.
  - Échelle complète (`TAILLE == "complete"`) : tout le jeu, sur `appareil()`. Sur GPU (T4, 16 Go, si le moteur l'a décidé) : `torch.float16` pour l'inférence des gros modèles, entraînement en précision mixte (`fp16=True` quand `appareil() == "cuda"`), lots adaptés à 16 Go, mémoire libérée entre les approches (`del`, `gc.collect()`, `torch.cuda.empty_cache()`). Le même code doit tourner sur CPU.
- Reproductibilité : `GRAINE` partout (découpages, échantillons, entraînement), aucun mélange aléatoire sans graine.
- Robustesse : vérifie colonnes et types ; une sortie de LLM illisible compte comme erreur et son taux est rapporté ; pas de boucle sans borne ; barres de progression désactivées (`disable=True`) ; lots de taille raisonnable pour la mémoire.
- Installation : pas de `!pip`, `%pip` ni `subprocess` pour installer. Déclare dans `dependances` les seuls paquets absents de : $preinstalles.
- Lisibilité : cellules de 80 lignes au plus, noms explicites, commentaires utiles, pas de code mort.
- `enregistrer_resultats` attend : `{"metrique_principale": str, "sens": "max" | "min", "jeu": {"nom": str, "config": str, "split": str, "n_exemples": int}, "approches": [{"nom": str, "role": "reference" | "nouvelle", "metriques": {nom: nombre}, "ic95": {nom: [bas, haut]}, "latence_ms": {"p50": ..., "p95": ...}, "notes": str}]}`. Mêmes clés de métriques pour toutes les approches, dans les deux phases. Les nombres sont des `float` Python (pas des types numpy).
- `protocole` : 3 à 6 phrases (données, découpage, réglages, métriques). `ecarts_sandbox` : ce qui diffère du protocole complet (tailles, substituts), chaîne vide sinon. `limites` : 2 à 5 points honnêtes.
